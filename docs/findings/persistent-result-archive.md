# Persistent numerical result archives and on-demand investigation
Status: local Stage 7.2.1 prototype, offline verified; no AI tool access to persistent records yet.

## Pattern
Separate conversational context, opt-in debug logs, and persistent scientific evidence. A result archive should be useful independently of AI. Record immutable originating inputs, stable result and operation identifiers, schema, units, complete numerical arrays where affordable, missing values explicitly, diagnostic provenance, and scope limits. Keep indices compact; never supply a whole archive to a provider by default. Deduplication must respect input identity, result data and operation provenance. Amplitude normalization updates are not independent solves.

Use bounded storage, explicit user controls, retention and pinning. Pinned records count toward the budget; refuse a write rather than silently evict pinned data. Disclose cleanup triggers, database overhead, sensitivity, export retention and failure modes. A storage failure must not destroy a numerical result or interrupt normal application use.

## Prototype evidence
The first target implements a local compressed JSON/SQLite archive, explicit opt-in (persisted), 30-day/500 MiB compressed-payload defaults, configurable retention and quota, pin/delete/export, bounded record sizes and checksums. Frequency sweeps include complete retained grids and complex indices with selected diagnostic fields and per-mode originating operation IDs. No field grids or fits, no automatic import of older logs, no complete solver restart guarantee. Single-mode power metadata may be updated for the same result ID. All archive contents and implementation remain target-local. Archive data is not exposed to the model in this stage; existing in-process history comparisons remain unchanged.
80 unit tests, two archive GUI tests and six existing focused result/sweep GUI tests passed. Synthetic 10,000 mode-grid points: compressed 186,644 bytes, DB 204,800 bytes, capture+write 0.119 s, read 0.028 s. 100,000 points: compressed 1,811,468 bytes, DB 1,830,912 bytes, capture+write 0.581 s, read 0.245 s. Single measurements in Linux, not production guarantees. Synchronous bounded persistence may delay GUI completion; Windows, full regression and live provider verification outstanding.

## Proposed next capability
Expose separately authorized, typed read-only tools for listing results, selecting a record, retrieving ranges and computing comparisons deterministically. Do not permit arbitrary file paths or model-generated commands. Bound tool steps, time, bytes and output; distinguish tool failure from absent evidence. Explicitly approve archive access and external transmission scope before provider calls. Use actual tool start/completion events for user-visible activity and cancellation; avoid speculative progress, fake percentages or fabricated internal reasoning. Treat model-directed retrieval and controlled solver execution as distinct permission levels. Investigate provider support before choosing a structured-call protocol. Evaluate retrieval correctness and ambiguous domain cases with known evidence before enabling autonomous execution.
