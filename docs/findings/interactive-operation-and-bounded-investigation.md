# Interactive operation, bounded investigation and inspectable evidence

Status: proposed design and evaluation guidance for review; not a shared runtime or a claim that all features are implemented. Builds on [controlled detached execution](controlled-detached-execution.md), [progress-aware coordination](progress-aware-coordination-and-permissions.md) and the [workflow acceptance checklist](../integrations/workflow-evaluation-checklist.md).

## Two complementary execution intents

An interactive operator changes the visible application workspace on explicit request and supports subsequent manual interaction. A detached investigator runs approved calculations on immutable copies, without changing the user's working configuration or display. These should share typed application actions, validated input snapshots, execution/provenance and result retrieval; they differ in presentation and permission to mutate working state. Opening a result for inspection is not consent to apply its originating settings or replace current results. Prefer a read-only result viewer first, then an explicit reversible apply operation with a state/version check. Do not rerun a completed operation merely to display it. Result references must distinguish request-local, session-local and persistent lifetimes; retention and permissions remain independent of display.

A first live controlled detached execution completed and was archived. The user could not directly see the numerical plot in the workspace, revealing a usability gap despite successful execution. The subsequent answer involved 16 calls to the same retrieval tool, all logged as successful, but reported incomplete coverage. Provider request intervals accounted for most of the end-to-end latency in this single trial. The exported event log lacked actual tool arguments/results; the cause of the reported gap is unknown. This motivates testing exact coordinate retrieval, pagination, compact paired summaries, and result coverage separately from transport success, not assuming that the solver lost roots or simply increasing tool limits. No target geometry, data, raw logs or code are included here.

## Goal preservation and scientific initiative

Keep a host-owned investigation record separate from model-generated conversation summaries. Preserve the original objective and user constraints verbatim, authorized scope and immutable baseline, resource budgets and actual execution ledger. The model may propose hypotheses, next discriminating checks and stop criteria, but cannot silently overwrite the objective or grant itself additional scope. Track verified observations with evidence IDs, uncertainty, alternatives and unresolved questions; distinguish model interpretation from deterministic evidence. Store interesting tangents as proposed follow-ups. Re-anchor every planning step to the objective and current evidence; validate state transitions and maintain a compact evidence index. Compression must retain provenance, permission revocation and conflicting observations; do not treat model-generated summaries as raw evidence. Re-evaluate after a user goal change rather than automatically continuing a stale investigation.

Use an opt-in initiative control distinct from execution authorization. Candidate levels: disabled, conservative (necessary checks), balanced (material improvements or promising anomalies), exploratory (actively examine relevant alternatives). Balanced is a proposed default *after* opt-in, not permission to run at startup or while idle. Before each job, identify the decision or hypothesis it informs, why retained evidence is insufficient, which outcome could change the answer, and estimated total cost including model round trips. Prefer an inexpensive existing result or targeted check. Do not chase minor uncertainties, force agreement with a favored hypothesis, or treat every unusual diagnostic as a defect. Curiosity is valuable but should be relevant, testable, and bounded. Independent hard caps on operations, compute, memory, time, requests and bytes remain application-owned; estimates and model assessments are not reliable cost guarantees. Require explicit escalation for expensive, destructive or out-of-scope tasks. Stop when evidence is adequate, no material progress is likely, or limits/revocation intervene; report partial evidence and unresolved questions without claiming completion.

## Inspectable presentation, without premature GUI standardization

A compact conversation sidebar can coexist with existing interactive application views and an optional expanded answer/investigation workspace. The latter might support longer explanations, comparisons, tables, actual plots, assumptions and result references. Start with a minimal result browser and a way to open a computed result, then learn from real usage before standardizing layouts. Numerical tables and plots should be rendered by deterministic application code from validated result data, not reconstructed from model prose. A model can propose which stored results, columns, quantities and plot ranges to present through typed descriptors; the host validates references, units, supported plot types, resource limits and permissions. Missing values stay missing; partial outcomes, input snapshots, and uncertainty are visible. Model text is untrusted; do not execute generated HTML, scripts or arbitrary plot code. Support text-only fallback, normal non-AI workflow, and explicit export. Viewing a local result does not imply authorization for provider transmission, permanent storage, or applying it to the working state.

For longer tasks, consider showing a supported preliminary answer plus actual ongoing activity, then a distinct supplementary finding or correction. This requires actual application task handling, explicit scope, cancellation, result lifetime and concurrency semantics; not a promise of asynchronous capability in the current implementation. Do not fabricate progress or reveal internal reasoning.

## Proposed acceptance cases

- Same approved computation via conventional and detached routes: compare exact inputs, grid, output/status and diagnostics; opening a completed result is read-only, does not rerun it, and preserves the workspace. Test partial, deleted, unavailable and non-persisted results and later manual adoption.
- Retrieval: request separated coordinates and contiguous intervals; verify exact coverage, paired quantities, selected diagnostics, missing vs omitted values and continuation tokens; test large payload and output limits. Measure calls, bytes and latency before/after.
- Ordinary conceptual question and existing-result question: no unnecessary computation. A deliberately ambiguous outcome: choose a discriminating inexpensive check when authorized. A costly research goal: request bounded escalation. Include false-positive anomaly controls and promising opportunities missed by the agent.
- Multi-step task with tempting tangent, contradictory evidence, repeated no-progress steps, context compaction, changed user objective and scope revocation: verify preserved objective, evidence lineage, meaningful stopping, no unauthorized job and no duplicate launch.
- Presentation: independently compare every numeric cell and plotted coordinate to its source; make partial/stale status visible. Test sidebar and expanded workspace at realistic window sizes with conventional controls reachable.
- Evaluate model initiative and goal drift empirically across repeated tasks. Track time to useful answer, total latency, compute consumed, relevant checks missed, unnecessary jobs, scientific correctness and human intervention. A single successful demonstration is not general reliability.

These are review proposals; target-specific adapters, numerical data, tests and layouts remain in the target application. Do not establish a mandatory universal UI or autonomous agent architecture before cross-application evidence.
