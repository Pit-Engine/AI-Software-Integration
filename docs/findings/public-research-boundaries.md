# Public research across a separate data boundary

Status: first-target Stage 7.5 prototype, verified with synthetic transport and GUI tests, live web search not yet verified.

## Reusable pattern
An assistant may need both private application evidence and public documentation/literature. Unified conversation does not imply unified data permissions. Institutional model access does not authorize sending internal context to external search engines. Keep the public search request isolated from ordinary model conversation, attachments, tool outputs, histories and application state. Enable search separately, make the exact proposed public query reviewable and require approval before external submission. A model can inadvertently place sensitive material in a standalone query; a confidentiality instruction is not a data-loss-prevention guarantee. A denied query should return an explicit unavailable-evidence result, allowing the original question to proceed. Do not silently broaden scope, retry via another provider, or automatically open source links.

When a provider exposes different protocols for native local function calling and public retrieval, implement them as distinct bounded request paths; verify each with public/synthetic fixtures. A successful native tool roundtrip does not prove public search works. Keep provider-specific flags in the provider adapter rather than in application physics or model-generated arguments. Count both types of request against investigation time, call and byte budgets; display actual activity and distinguish a proposed/approved query from a completed search.

## External evidence and citation semantics
Extract source metadata from actual structured responses rather than model-written links. Assign request-local IDs and append a deterministic source list. Preserve URL/title/snippet provenance; normalize and bound output. Treat all externally retrieved text as untrusted. A returned URL is not proof the publication was independently opened, supports a claim, is peer reviewed or is even reachable. Do not treat provider prose citation indexes as equivalent to locally assigned IDs unless mapping is verified. If metadata is missing, malformed or unsupported, explicitly report that the external evidence is unavailable, rather than passing an ordinary generated answer off as sourced research. Validate source references and test citation entailment separately. Do not infer full-text access from snippets. Render URLs as non-executing text or validated user-initiated links.

## Prototype evidence
First target: separately opt-in public search in ordinary native Ask, one exact-query approval and at most one public request per investigation. DESY provider guide documents legacy web search with features.web_search=true and params.function_calling=legacy; user previously verified native synthetic tool roundtrip, but this web path has not been tested live in the client. Only one user message containing the approved query is transmitted on the separate public path. The native response continues with bounded source metadata and snippets; final deterministic source list. The web capability alone does not grant archive access. Six shared tool calls, seven native requests plus at most one public request, existing aggregate wire/output limits and checkpoint time limits; consent wait counts toward time. No provider secrets, actual application data or code included in framework. 131 AI unit tests and 26 focused GUI tests passed, including combined local/public context isolation, denial, cancellation, disabled access, missing/malformed metadata and source display. No independent live source verification, Windows or full numerical regression. Source parsing is based on documented and synthetic response shapes, not observed production sources. Live public-only protocol probe and natural automatic tool-selection/citation evaluation are next.
