# Integrated assistant layout and preservation of application usability

Status: first-target Stage 7.5.2 prototype, tested in mapped Linux Tk windows, Windows/high-DPI user evaluation pending.

An assistant that accumulates controls, transcript, activity and source-status elements can consume space needed by the underlying application. The first user reported that a vertically stacked layout hid layer editor values and the confirmation control, and suggested a right-side assistant. This is an integration regression even if the AI works correctly. Treat conventional application usability as an independent acceptance criterion.

A resizable, collapsible side pane can preserve vertical working space and remain available across application tabs. It trades height for width, so do not merely relocate the assistant and assume the host layout remains usable. Test responsive reflow, scroll/focus access to confirmation buttons and all input fields, minimum practical window size, long status messages, active cancel controls, and normal full-width mode. Hide/show should not recreate the assistant or reset draft input, transcript, granted permissions or active investigation; hiding must not imply cancellation. A persistent entry point should restore access and progress/stop controls. Keep layout independent of provider and application calculations. Different applications and displays may warrant different placement; this is not a universal fixed docking requirement.

First-target evidence: right-hand pane with draggable divider, header show/hide, compact controls and wrapped status, dedicated scrollable structure editor and adaptive form reflow. 141 AI unit tests and 28 focused GUI tests passed, including 3 new mapped-layout tests at 1260x850, 1100x740 and 960x600. The tests exercise actual selected-field update, pane resizing, preserving conversation/draft, switching five tabs, and Ask/Stop visibility. An initial assertion compared Tk window objects to strings and was corrected. Other tabs are not all redesigned for narrow widths; hide pane to regain full width. Windows and full numerical regression remain outstanding. No target implementation, screenshots, raw logs or scientific data in the framework.

## Separate live provider checkpoint

The revised public-only probe returned usable grouped structured source metadata (3 URLs, 9.12 s) and a natural GUI investigation completed two distinct approved public searches (5 unique returned URLs, 44.9 s), as reported by the user. Actual group shape includes source metadata, aligned document/metadata arrays, and distances. This establishes working metadata extraction for that response and multiple live calls, not source validity, scientific correctness, reliable loop detection or populated archive retrieval. Earlier absence of usable URLs remains an observed failure; cause not established. Keep public/private isolation and deterministic provenance. Never interpret server-reported routing metadata as safe to share verbatim: it can contain sensitive fields even when a structural-only probe avoids values.
