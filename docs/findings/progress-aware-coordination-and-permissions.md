# Progress-aware read-only coordination and permission scope

Status: first-target Stage 7.5.1 local prototype; offline verification only for new behavior.

## Evidence motivating the change
A live automatic native public-search call and tool-result roundtrip succeeded, but public search returned no usable structured source metadata. Two prior responses asked for approval in prose instead of invoking the tool and letting the application present approval. Distinguish model tool selection, actual execution, authorization, transport success, metadata parsing and evidence validity; one does not establish the others. The user also reported unproductive loops in a different coding-agent workflow; no traces of those loops were analyzed.

## Permission and provider boundaries
A remembered ordinary provider authorization can reduce startup friction while retaining an explicit user-initiated request trigger. Scope saved authorization to version, provider endpoint/model and separately approved broader data access. Do not migrate old session consent silently. Provide reset and optional per-request review. Keep credentials separate. Public search retains independent default-off capability and exact-query review by default; optional explicit public-only authorization expires with conversation, restart or revocation. Model-generated isolated search text may still inadvertently contain private data: broader consent is unsuitable for confidential conversations and is not automatic confidentiality protection. Stop an active investigation before revoking further access. No automatic startup or background requests. The application owns permission checks; instruct the model not to solicit duplicate approvals in prose. Continue isolating external search request bodies.

## Progress and bounded execution
Replace very small fixed limits with independent hard ceilings and an observable progress heuristic. Canonicalize tool name and arguments; do not reexecute identical successful reads within a frozen request scope, and direct the model to earlier evidence. Count invalid/skipped calls too. Treat repeated same-call failures and consecutive no-novel-result outcomes as signals for stopping, not proof of scientific failure. Different pages/results, new public source URLs and legitimate changes may justify continued investigation. Use actual tool outcomes rather than model self-reports. Preserve deterministic progress and stop events. Reserve final synthesis with tools disabled where possible; when request-size/time/transport constraints prevent synthesis, report bounded retrieved evidence and explicitly mark partial outcome. A fresh user request can continue with a new finite budget. Allow explicitly selected larger one-shot budgets without widening data or action authorization. Do not infer relevance from mere novelty; exact fingerprints can miss semantic loops or suppress useful repetition. Future mutation/execution tools need operation IDs, idempotency, state/provenance checks, distinct execution budgets, and no blind retry after ambiguous outcome. This prototype is read-only.
